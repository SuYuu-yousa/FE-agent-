# 存储（前端持久化）

------

# 前端持久化

## 基础概念

- 什么是前端持久化（为什么需要在客户端存储数据）

  **将数据存储在客户端（浏览器）中，使其在页面刷新、关闭甚至重启浏览器后依然能够保留和恢复** 的技术。

- 持久化 vs 临时存储的区别

  - 关了浏览器还在就是持久化，否则就是临时存储,特例：cookie过期，sessionstorage

  - *持久化的核心是* **数据写入磁盘**，临时存储的核心是 **数据只在内存中**。

- 前端持久化的常见应用场景（用户偏好、离线缓存、表单草稿、Token 存储等）

  - token：登录后把 token 存下来，下次请求带上（Cookie 或 localStorage）。
  - 表单：草稿自动保存，用户误关页面/刷新不丢输入。

------

## 二、各种存储方案详解

### 1. Cookie

- 机制：服务端 `Set-Cookie` 种下，浏览器之后每次请求自动带上（`Cookie` 请求头），适合登录态。
- 属性：`Expires`/`Max-Age`（过期）、`Domain`/`Path`（作用范围）、`HttpOnly`（JS 读不到，防 XSS）、`Secure`（只走 HTTPS）、`SameSite`（Strict/Lax/None，防 CSRF）。
- 大小与数量：约 4KB、每域 20~50 个。
- 优缺点：自动携带省事；但每次请求都带（浪费带宽）、小、明文，==适合放身份标识，不适合放数据==。
- 前沿：第三方 cookie 被淘汰，大厂改用 `Partitioned Cookie`（CHIPS 分区）做跨站登录/埋点。

### 2. Web Storage

- **LocalStorage**：约 5MB、永久（手动删才没）、同源共享、同步 API、无过期时间。
  - 只支持字符串：对象/数组必须 `JSON.stringify` 存、`JSON.parse` 取。
  - 适用：用户偏好、主题、不敏感 token。
- **SessionStorage**：会话级，关标签页就没了；**标签页隔离**（同源不同标签页各存各的，新开 tab 复制初始值后互不影响）。
  - 适用：表单临时数据、当前会话状态。

### 3. IndexedDB

- 概念：浏览器内置 **NoSQL 事务型数据库**，容量大（百 MB~GB）、异步、存结构化数据（对象/二进制/Blob）。
- 核心概念：Database（库）→ ObjectStore（表）→ Index（索引）→ Transaction（事务）→ Cursor（游标遍历）。
- 原生 API 啰嗦，常用封装：`Dexie.js`、`idb`、`localForage`。
- 适用：大量结构化数据、离线应用、聊天记录、缓存列表。

### 4. Cache API / Service Worker 缓存

- Cache API：`caches.open('v1')` → `cache.put(req, res)`，存的是 **Request/Response 对**（不是普通数据）。
- 配合 Service Worker 做离线/PWA。
- 缓存策略：Cache First（缓存优先）、Network First（网络优先）、Stale While Revalidate（先用缓存、后台更新）。

### 5. 其他/补充方案

- WebSQL（已废弃，了解即可）。
- File System Access API（新兴，直接读写本地文件，需授权）。
- OPFS（源私有文件系统，Worker 里高性能文件读写，配合 WASM 大文件）。

## 四、实践中的关键问题

### 1. 安全性

- XSS 能读到 localStorage/sessionStorage（JS 可访问）→ 偷 token。这也是「JWT 不建议存 LocalStorage」的原因之一。
- Token 存储：Cookie（HttpOnly 防 XSS，但 CSRF 要另防）vs LocalStorage（方便，但 XSS 能偷）。大厂偏 HttpOnly Cookie + SameSite。
- 敏感数据加密存储（但密钥也在前端，只能「防君子」）。

### 2. 数据序列化与反序列化

- `JSON.stringify/parse` 的坑：`undefined`/函数/`Symbol` 被丢掉、`Date` 变字符串、`RegExp` 变 `{}`、循环引用抛错、`NaN/Infinity` 变 `null`。
- 特殊类型手动处理：Date 存时间戳、RegExp 存 source+flags。

### 3. 存储容量管理

- 超限：写入 catch `QuotaExceededError`；查配额 `navigator.storage.estimate()`。
- 淘汰：空间不足时浏览器按 LRU 淘汰（Storage Eviction），「持久化」的也可能被清，别把关键数据只存本地。

### 4. 跨标签页通信与同步

> 已移至 [[跨端 跨页面通讯]]（页面间通信节：storage 事件 / BroadcastChannel / SharedWorker / postMessage）。

## 五、封装与工程化实践

- 统一存储接口封装（适配多种底层方案）。
- 过期时间机制：给 LocalStorage 加 TTL，存 `{ value, expire }`，读时判断过期。
- 命名空间 / Key 管理：加前缀防冲突（`app:user:xxx`）。
- 版本迁移：数据结构升级时做版本号 + migrate。
- 常用库：localForage（自动降级 IndexedDB/WebSQL/localStorage）、store.js、unstorage。

------

## 六、场景化最佳实践

- 登录态持久化：HttpOnly Cookie（主）+ 前端内存/内存缓存（减少重复请求）。
- 表单草稿自动保存：localStorage/sessionStorage 定时存，恢复时回填。
- 离线优先：Service Worker + Cache API 缓存静态资源，IndexedDB 缓存数据。
- 大文件/大数据：IndexedDB（或 OPFS），别硬塞 localStorage。
- SSR/SSG：注意「无 window 环境」，localStorage 要 `typeof window !== 'undefined'` 判断或 useEffect 里访问。

------

## 七、面试高频问题整理

- **Cookie/LocalStorage/SessionStorage 区别** → 容量（4KB/5MB/5MB）、生命周期（可设/永久/会话）、是否随请求（是/否/否）、作用域。
- **为什么不建议 JWT 存 LocalStorage** → XSS 能偷；放 HttpOnly Cookie 更安全（CSRF 用 SameSite/Token 防）。
- **IndexedDB 事务机制** → 所有读写必须在 Transaction 里；同一 ObjectStore 的读写事务串行（保证一致性）；事务自动提交。
- **如何实现 LocalStorage 过期** → 存 `{ value, expire }`，读时比较时间戳，过期删。
- **前端存储安全隐患** → XSS 偷数据、明文存储、别存敏感信息、存储可能被用户/插件读。

# 跨端兼容与选型

> 面试高频：跨端方案选型、兼容性实战坑（1px / safe area / dvh / WebView 差异）。已填好答案。

## 一、跨端是什么、为什么需要

- 跨端 = 一套代码（或尽量少的代码）跑在多个终端：Web/H5、小程序、App（iOS/Android）、桌面（Win/Mac/Linux）。
- 为什么：降本（少招多端开发）、提效（一次开发多端上线）、体验一致。
- ==一句话：用尽量少的代码，覆盖尽量多的端==

## 二、跨端方案谱系（从轻到重）

### H5 / 响应式（最轻）
一套 Web 页面，靠响应式适配不同屏幕。成本最低，但体验和原生有差距、拿不到系统能力。

### 小程序系
微信小程序原生 / uni-app（Vue）/ Taro（React）：一套代码编译到多平台小程序 + H5 + App。国内主流。

### 跨端 App 框架
React Native（JS → 原生）/ Flutter（Dart，自绘渲染）：真正跨 iOS/Android，体验接近原生。

### 桌面
Electron（Chromium + Node，成熟、重）/ Tauri（系统 WebView + Rust，轻、新）。

> **三种技术形态的本质**：Electron = 内嵌 Chromium + Node（带 Node 能力的浏览器）；RN = JS 引擎调原生 API（非浏览器，网络是原生实现）；WebView = 原生里嵌小浏览器（小程序 / App 内 H5，阉割版）。

## 三、选型怎么选（结合场景）

- 要触达广、快速验证 → H5。
- 国内、微信生态、多平台小程序 → uni-app / Taro。
- 要原生体验、跨 iOS/Android → RN / Flutter。
- 桌面工具、团队只会 JS → Electron；追求体积/性能/安全 → Tauri。
- ==没有银弹，按「目标端 + 团队技术栈 + 体验要求」选==

## 四、跨端兼容实战坑 ⭐（前端通用）

### 1px 问题
高 DPR 屏幕 1 CSS px 对应多个物理像素，`border:1px` 偏粗。方案：伪元素 + `transform: scale(0.5)`、`0.5px`。

### safe area（安全区）
刘海屏/底部横条，内容要避开：`env(safe-area-inset-*)` + `viewport-fit=cover`。

### dvh / svh / lvh
移动端地址栏动态伸缩，`100vh` 不准；用 `dvh`（动态视口高度）做全屏。

### WebView / 浏览器差异
不同端内核不同（iOS WKWebView、Android Chromium、微信 X5），CSS/JS API 支持不一，要 feature detect + polyfill。

### 小程序特殊
rpx 单位、wx API（不能用 DOM）、包体积限制（主包 2M）、setData 性能。

## 五、Tauri vs Electron（2024–2026 新知识，加分项）

- Electron：捆绑 Chromium，成熟、生态全，但体积 80–150MB、内存高、纯 JS 上手快。
- Tauri 2.0：用系统 WebView + Rust 后端，体积 ~几 MB、内存低、启动快、更安全（前端沙箱 + 权限模型）；2.0 还支持打包 iOS/Android。
- ==选 Tauri：要小体积/高性能/省资源、愿意写 Rust；选 Electron：纯 JS 团队、要生态成熟、快速开发==
- Tauri 坑：老系统没 WebView2 会跑不起来、Linux 各发行版 WebView 版本碎片化。

# 常考场景设计 + 错误监控

> 面试高频：场景设计题（结构化答题）、前端错误/性能监控。已填好答案。

## 一、场景设计题「结构化答题」方法论 ⭐

### 拿到题先别急着写代码，按这五步
1. **需求澄清**：先问关键约束（用户量、实时性、数据量、端），没给的合理假设并说出来。
2. **架构/分层**：前端（页面/组件/状态）、通信（接口/协议）、后端（接口/存储）怎么摆。
3. **核心数据流**：一条主链路走通（如：用户操作 → 请求 → 后端处理 → 响应 → 渲染）。
4. **关键细节**：扣题的技术点（长列表→虚拟滚动；上传→分片+断点续传）。
5. **异常/优化**：出错怎么办（重试/降级/兜底）+ 性能（缓存/懒加载/节流）。

### 答题技巧
- ==用「结构化」代替「东一句西一句」，让面试官看到你会拆解==
- 先给总览（一句话方案），再展开细节，最后主动说边界和取舍。

## 二、高频场景速答

### 长列表（万级数据卡顿）
虚拟滚动（只渲染可视区 + 上下缓冲）、分页/无限滚动、key 复用、避免整列表 setState（按行更新）。

### 大文件上传
分片（slice）上传 + 断点续传（记录已传分片）+ 秒传（hash 校验）+ 并发控制 + 进度条。

### 实时协作 / 即时通讯
WebSocket（双向）+ 心跳 + 重连；冲突用 OT/CRDT；AI 流式用 SSE（单向，串周二/周五）。

### 秒杀 / 高并发
前端：防重复提交（按钮置灰）、排队、倒计时、CDN 静态化；后端：限流、削峰、库存缓存。

### 埋点 / 数据上报
前端 SDK 采集（点击/曝光/时长），批量上报、节流、失败重试，避免阻塞主线程（sendBeacon）。

## 三、前端错误监控 ⭐

### 监控三块
- 错误监控：JS 异常、Promise rejection、资源加载失败、接口错误。
- 性能监控：加载时间、Core Web Vitals（LCP/INP/CLS）、接口耗时。
- 行为监控：用户路径、埋点、会话回放（Session Replay）。

### 错误怎么采集
- `window.onerror`（JS 运行时错误）、`unhandledrejection`（Promise 拒绝）、`error` 事件（资源加载失败，捕获阶段）。
- React 用 **Error Boundary** 捕获渲染错误并给 fallback UI。
- 接口错误：统一 axios/fetch 拦截器上报。

### sourcemap 还原
- 生产代码压缩混淆，堆栈不可读；sourcemap 把压缩代码映射回源码。
- ==.map 绝不能发到 CDN（源码泄露），只上传到 Sentry，服务端符号化还原==
- 还原前后对比：`main.a3f2.js:1:4829` → `CheckoutForm.tsx:42`。

### Sentry 接入（现代主流）
- `@sentry/react` / `@sentry/nextjs`，配 dsn / release / environment。
- 带 breadcrumbs（用户操作路径）、setUser、tag（按路由/功能分组）。
- 降噪：allowUrls 过滤三方脚本、beforeSend 脱敏 PII、采样。

## 四、性能监控与 RUM

### RUM（Real User Monitoring）
从真实用户采集数据，看 LCP/INP/CLS 的 p75/p90，按设备/地区/网络分段；配合合成监控（CI 里自动化测）做质量门禁。

### 2025 趋势（加分项）
- RUM 大众化（Sentry/Vercel Speed Insights/PostHog 都便宜）。
- Session Replay 伦理规范化（maskAllText 遮罩敏感信息）。
- AI 异常检测（LLM 做错误分组、根因分析、告警降噪）。

## 五、监控体系设计（工程化）

- 链路：**采集（SDK）→ 上报（批量/节流/离线缓存）→ 存储分析 → 告警 → 可视化面板**。
- 关键：统一 release/环境、traceID 打通前后端、采样率控制成本、告警规则（新错误/错误率超阈值/回归）。
- ==一句话：监控不是「装上就完」，是「采集—上报—分析—告警—定位」闭环==

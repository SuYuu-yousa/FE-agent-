# 性能优化

> 目标：前端性能优化面试按「五个阶段」串——加载、首屏、运行时、构建、监控测量。每项用短要点；已有专题的只写一句结论 + 指向，不重复展开。

## 一、加载阶段（资源怎么更快到）

### 1. CDN
==就近节点：静态资源放 CDN，用户访问离他最近的边缘节点，减少物理距离和延迟。==

### 2. 压缩 gzip / brotli
> 要写：brotli 比 gzip 压缩率更高（约 15-20%），但服务器 CPU 开销略大；现代浏览器都支持，优先 brotli。

### 3. 缓存（强缓存 / 协商缓存）
==强缓存 Cache-Control 命中不发请求；协商缓存 ETag/304。→ 详见 [[浏览器相关]]。==

### 4. 资源体积（代码分割 / tree-shaking / 图片压缩）
> 要写：代码分割按需加载；tree-shaking 摇掉没用到的代码；图片用 webp/avif。

### 5. 协议 HTTP/2 / HTTP/3
> 要写：HTTP/2 多路复用（一个连接并发多个请求）；HTTP/3 基于 UDP，弱网更快。

### 6. 预加载 preload / prefetch / dns-prefetch / preconnect
> 要写：preload 本页高优先级、prefetch 下页低优先级、dns-prefetch 提前解析域名、preconnect 提前建连。

### 7. 域名拆分 vs 收敛
> 要写：HTTP/1.1 每域名并发上限约 6，靠多域名突破；HTTP/2 多路复用后反过来收敛成单域名。

### 8. 关键 CSS 内联
> 要写：首屏关键 CSS 内联进 HTML，省一次请求、避免闪屏。

### 9. 图片优化细分
> 要写：srcset 响应式、雪碧图/iconfont 减少请求、小图 base64 内联省请求。

## 二、首屏阶段（页面怎么更快出内容）

### 1. SSR / SSG
==服务器先渲染好 HTML，首屏快 + SEO 好。→ 详见 [[next nuxt BFF层 水合]]。==

### 2. 关键渲染路径
> 要写：CSS 放 head、JS defer/放底部，别让 JS 阻塞解析。

### 3. 图片懒加载 loading="lazy"
==滚到视口才加载，省首屏流量。==

### 4. 骨架屏 / 字体优化
> 要写：骨架屏撑住布局避免跳动；字体 font-display: swap 避免文字空白。

### 5. 指标 FCP / LCP / CLS
==FCP 首次内容、LCP 最大内容(核心 <2.5s)、CLS 布局偏移(<0.1)。→ 详见 [[浏览器相关]]。==

### 6. 白屏 vs 首屏
> 要写：白屏 = HTML 加载到开始渲染；首屏 = 第一屏内容完整显示；两者都是面试常问的测量点。

## 三、运行时阶段（页面怎么更流畅）

### 1. 减少重排重绘 ⭐
==DocumentFragment 批量插、批量改 class / 一次 cssText、动画 transform/opacity、读写分离、rAF 合并。→ 详见 [[浏览器相关]]。==

### 2. Worker 线程调度 ⭐
==Web Worker 独立线程，把耗时计算挪出主线程，postMessage 通信，不卡 UI。==

### 3. 长任务切片 / 时间分片
> 要写：把一个大任务拆成多个小任务分帧执行，避免长时间阻塞主线程（React Time Slicing 思路）。

### 4. requestIdleCallback
> 要写：浏览器空闲时执行低优先级任务，适合埋点 / 预计算这类不紧急的活。

### 5. 防抖 / 节流
> 要写：防抖 = 停止触发后 N 秒执行（搜索框）；节流 = 固定间隔最多执行一次（滚动 / resize）。

### 6. 虚拟列表
> 要写：长列表只渲染可视区域，其他用占位，避免一次渲染几千个 DOM。

### 7. React 层 memo / useMemo / useCallback
> 要写：memo 跳过 props 没变的 re-render；useMemo 缓存计算结果；useCallback 缓存函数引用。

### 8. 事件委托
> 要写：父元素统一监听，代替每个子元素各绑一个，减少监听器数量。

### 9. 内存泄漏
> 要写：闭包、定时器、事件监听、全局变量没清理会导致内存涨；用完 clearInterval / removeEventListener。

## 四、构建阶段（打包怎么更优）

### 1. 代码分割
==按需拆 chunk，首屏只下必要代码。→ 详见 [[专题：js从哪来，又到哪去？]]。==

### 2. tree-shaking
> 要写：ESM 静态 import 让打包器能摇掉没 import 的代码（死代码消除）。

### 3. 压缩混淆
> 要写：产物 minify（去空格注释、变量名缩短），减少体积。

### 4. 文件名 hash + 长缓存
> 要写：内容变了文件名变，浏览器缓存自然失效；没变的走强缓存。

## 五、监控测量（怎么知道自己快不快）

### 1. Performance API
> 要写：performance.timing 拿各阶段耗时；Navigation Timing / Resource Timing 拿资源和导航数据。

### 2. 首屏 / 白屏 / LCP 怎么测
> 要写：白屏用 performance.timing 算；首屏看关键元素出现；LCP 用 PerformanceObserver 监听。

### 3. 性能埋点 / 上报
> 要写：前端采集指标，Navigator.sendBeacon 上报，做监控大盘和告警。

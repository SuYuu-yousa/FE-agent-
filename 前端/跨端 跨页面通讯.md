# 跨端 / 跨页面通讯

> 主线：一条消息怎么从一个「执行环境」送到另一个「执行环境」。这里的另一端**不是服务器**（那是 [[网络相关 http nginx]]），而是浏览器内部的另一个页面 / Worker，或者原生 App。底层高度统一——**postMessage 是贯穿始终的核心**，其余都是它的变体或封装。

## 一、页面间通信（浏览器内部：页面 ↔ 页面 / Worker）

### 1. postMessage ⭐ 核心
- 跨窗口、跨 iframe、与 Worker 通信的统一 API：`target.postMessage(data, targetOrigin, [transfer])`。
- **能跨源发**（这是它和 BroadcastChannel 的关键区别），但必须显式写 `targetOrigin`，别用 `*`，否则敏感数据可能被恶意页面收走。
- 接收端 `addEventListener('message', e => { e.data / e.origin / e.source })`。

### 2. BroadcastChannel（同源广播）
- `new BroadcastChannel('name')` + `postMessage` / `onmessage`，同源多标签页 / iframe / Worker 之间广播。
- 比 storage 事件更通用：不依赖写存储、能传任意结构化数据；发送者自己也收不到（只广播给「别人」）。
- 场景：多标签页同步登录态、主题、登出通知。

### 3. MessageChannel（点对点）
- `const { port1, port2 } = new MessageChannel()`，port1 发 → port2 收。
- 常把 port2 通过 postMessage 传给 iframe / Worker，双方各持一端，实现**点对点**双向。

### 4. storage 事件（同源标签页联动）
- 同源下 A 页面 `localStorage.setItem`，其他标签页触发 `window.addEventListener('storage', e => e.key / newValue)`。
- 注意：**自己改不触发自己**；只对 localStorage 生效（sessionStorage 隔离不触发）。

### 5. SharedWorker（同源多页共享）
- 同源多页面共享**一个** Worker 实例：`new SharedWorker('w.js')` + `port.postMessage`。
- 场景：多标签页共享一条 WebSocket 连接、共享状态、做消息中转。

### 6. iframe 通信
- 现代：postMessage（跨域也行）。
- 老手段（了解即可）：`document.domain`（同一主域子域降级，基本废弃）、`location.hash`（改 hash 传值，单向）、`window.name`（可跨域存字符串）。

### 7. Web Worker 通信（与页面同机制）
- 也是 `postMessage` + `onmessage`，消息用**结构化克隆**传递（拷贝，不是共享内存）。
- 大对象（ArrayBuffer）可用 **Transferable** 转移所有权（零拷贝，转完原端不能用）；`SharedArrayBuffer` 可真正共享内存（需跨源隔离，见 [[安全相关]]）。

### 对比表

| 手段 | 是否同源 | 点对点/广播 | 关键点 |
|---|---|---|---|
| postMessage | 否（可跨源） | 点对点 | 显式 targetOrigin |
| BroadcastChannel | 是 | 广播 | 不依赖存储 |
| MessageChannel | 否 | 点对点 | 一对 port |
| storage 事件 | 是 | 广播（间接） | 依赖 localStorage |
| SharedWorker | 是 | 共享中转 | 多页共享一个实例 |

## 二、跨端通信（浏览器 ↔ 原生）

### 1. JSBridge（H5 ↔ App）⭐
- H5 跑在 WebView 里拿不到系统能力（相机/定位/扫码），要借原生。
- 原理：原生往 WebView 注入一个全局对象（Android `addJavascriptInterface`、iOS `WKScriptMessageHandler`），H5 调 `window.bridge.call(method, params, callback)`，原生执行完回调。
- 本质：一条消息（调用名 + 参数 + 回调 id）+ 一次回调，和 postMessage 一个思路。

### 2. Electron IPC（主进程 ↔ 渲染进程）
- 主进程（Node，管窗口/文件/系统）+ 渲染进程（Chromium，跑页面）通过 `ipcMain` / `ipcRenderer` 通信。
- 事件名 + payload，可同步可异步；场景：渲染进程读写文件、调系统对话框，发 IPC 给主进程。

### 3. 小程序（逻辑层 ↔ 视图层）
- 逻辑层（JS）与视图层（WXML）隔离、不共享变量，靠 `setData` 把数据序列化传过去（别大对象频繁 setData，有开销）。
- 小程序内嵌 web-view（H5）与小程序之间用 `postMessage` 通信。

# 组件设计与通信

> 目标：前端面试「组件化」核心。高频：组件拆分、受控/非受控、组合优于继承、通信方式。已填好答案。

## 一、组件化思想

### 为什么要组件化
复用、隔离、可维护、可测试；UI 拆成独立可组合的单元，改一处不影响全局。

### 怎么拆
单一职责、按 UI/业务拆、可复用抽公共、别拆太碎。经验：一个组件只做一件事，几百行就该拆。

## 二、props 设计 ⭐

### 好的 props
语义清晰、必需/可选、默认值、TS 类型约束；避免传大对象/传整个 store（用的时候没法知道依赖什么）。

### 状态提升
多个子组件共享的状态提升到共同父组件；受控思想——父组件持有状态，子组件只负责展示 + 回调。

## 三、受控 vs 非受控 ⭐

### 区别
受控 = 值由父 state 完全控制（input 的 value + onChange）；非受控 = 值在内部自管（defaultValue + ref 读取）。

### 场景
表单要实时校验/联动用受控；只提交时取值、性能敏感（如大列表输入）用非受控。

## 四、组合优于继承

### children / 插槽
用 children 或 props 传 JSX 组合，而不是继承；React 几乎不推荐继承（class 组件已被函数组件取代）。

### 例子
Card/Modal 外层固定、内容 children 塞。

## 五、组件通信 ⭐

### 父传子 / 子传父
props 下传、回调/emit 上传。

### 跨层
Context / provide-inject；避免 props 逐层传。

### 全局 / 兄弟
状态管理（zustand/pinia）、事件总线（少用，难维护）。

## 六、组件设计实际场景

### 通用组件 vs 业务组件
通用（Button/Modal/Table）抽进组件库；业务（UserCard）留在项目。通用组件要「配置化」，业务组件要「快」。

### 动态生成 UI（关联 Agent 岗）⭐

Agent 生成的 UI（tool call 结果、结构化数据）如何映射成组件渲染——组件要可配置、schema 驱动。

#### 思路
后端/Agent 不返回「写死的 HTML」，而是返回**组件描述**（schema），前端查表渲染：
`{ type: 'button', props: { label: '确认', variant: 'primary' } }` → `registry['button']` 渲染。

#### 四步
1. Agent 产出结构化数据（tool call 结果、JSON schema）。
2. 前端有「组件注册表 registry」：`{ button: Button, card: Card, table: Table }`。
3. 按 `type` 查表，把 `props`/`children` 传进去递归渲染（组件树）。
4. 兜底：未知 type 用默认组件/白名单过滤，防止 Agent 输出恶意或非法结构。

#### 要点
- 组件要「可配置」（props 驱动），不是写死。
- 数据（Agent 出）和 UI（前端出）解耦：Agent 只出数据，前端决定长什么样。
- 递归渲染 + 白名单，兼顾灵活和安全。
- ==一句话：Agent 负责「想做什么」，前端负责「长什么样」，中间用 schema 约定==

## 七、常用组件封装考查 ⭐

> 面试不只问「思想」，还会让你**具体封装一个组件**，考受控 / 边界 / 性能。

| 组件 | 核心考点（一句话结论） |
| --- | --- |
| 弹窗 Modal | 受控 `open/onClose`；用 Portal 挂到 body，避免父级 overflow/层级裁剪；遮罩点击关、Esc 关、锁滚动 |
| 表单 Form | 受控 value+onChange；校验抽成 rules；封装 Field/useForm 复用 |
| 虚拟列表 VirtualList ⭐ | 只渲染可视区那一段，其余用占位高度撑滚动条 |
| 无限滚动 / 懒加载列表 | IntersectionObserver 监听底部哨兵，触底拉下一页 |
| Select / AutoComplete | 受控 value；展开态、键盘上下选、点外部关闭 |
| 树形组件 Tree | 递归渲染子节点；expanded 集合控制展开折叠 |
| 拖拽排序 | HTML5 drag 或库；记录拖拽项和目标，重排数据 |
| 懒加载 React.lazy | 配合 Suspense 按需拆组件，减少首屏 |
| 通用组件 Button/Table | props 配置化（variant/size/columns），一处封装全局复用 |

### 虚拟列表（最常考）核心思路

- 一万条数据，只渲染屏幕上能看到的那 ~20 条。
- 外层容器固定高度 + `overflow: auto`；里面一个「撑高度」的假 div（总高 = 条数 × 每条高），保证滚动条正确。
- 监听 `scrollTop`，算 `startIndex = scrollTop / itemHeight`，`endIndex = startIndex + 可视条数`，只渲染这一截，上下用 padding/空白占位。
- ==一句话：只画眼睛看到的那一段，滚动条靠「占位高度」撑出来。==

### 无限滚动核心思路

- 列表底部放一个「哨兵」div，`IntersectionObserver` 观察它，一进视口就加载下一页。
- ==一句话：底部长个「眼睛」，看到它了就继续加载。==

### Modal 核心思路

- `createPortal` 把弹窗挂到 `document.body`，脱离父级 overflow/层级限制。
- 受控 `open`；遮罩 onClick 关、Esc 关、打开时锁 body 滚动。
